# 交易台设计规范（DESIGN-RULES）

> 本规范把外部设计方法落成**这个项目自己可执行**的规则：每条要么能被
> `scripts/design-check.py` 自动验收，要么在评审清单里有明确的检查动作。
> 方法来源：组件库约束用法（防风格拼贴）、impeccable 五维、《人人都是 UI 设计师》
> 20 条军规、logo-design-skill 的验收闭环。落地过程见 v12.1 收编记录（文末）。

## 0. 分层口径

| 层 | 范围 | 要求 |
|---|---|---|
| **N 层（新代码）** | `v12.css`、`index.html`、之后新增的 js/css | 八条硬性规则 **0 容忍**，脚本必须全绿 |
| **L 层（遗留）** | `app.css` 及旧组件 | 不阻断，脚本只报数量；**改动旧组件时顺带收编**，趋势必须向下 |

新增组件一律进 `v12.css`，禁止再改 `app.css` 加新样式。

## 1. 硬性规则（脚本自动验收）

| # | 规则 | 为什么（来源） | 检查 |
|---|---|---|---|
| R01 | N 层颜色必须全部走 `var(--*)` 令牌；`#fff` 仅允许用于深底文字 | 「只准在一个库里抄，间距配色严格吃全局变量」——风格拼贴的根源就是绕开令牌 | `R01` |
| R02 | 阴影只允许 `--shadow-s / --shadow / --shadow-l / --shadow-inset-hi / --shadow-hi-line / --shadow-rail / --focus-ring`；层次靠 1px hairline 与底色差 | 军规 19「慎用边框」的推论：阴影是更贵的分层手段，种类必须枚举受控 | `R02` |
| R03 | 进度条全站统一 `height:4px`、`border-radius:0`、无渐变 | 同一种元件两种长相 = 两个设计师。渐变进度条是「课程 App」遗风 | `R03` |
| R04 | 一屏只留一块深色面（`.hero` 在 index.html 中唯一） | 军规 02「别着急上色」：深色是最强的强调手段，两块深色面互相打架 | `R04` |
| R05 | 圆角只允许 `--r-xs:6 / --r-sm:9 / --r:13 / --r-lg:16 / --r-xl:20`；纯圆 `50%` 豁免 | 圆角种类是最隐蔽的风格漂移（v12.1 前同文件有 9 种字面值） | `R05` |
| R06 | 列表不得留白，必须有空态（有内容、有下一步动作），JS 渲染与 CSS 样式同时存在 | 军规 20「别忽视空状态」：空态是用户看到的第一个「页面」 | `R06` |
| R07 | `:focus-visible` 与 `prefers-reduced-motion` 必须存在 | 无障碍底线，不是可选项 | `R07` |
| R08 | HTML 内联样式只允许几何参数（padding/margin/flex/width/height/text-align）；颜色、字号、字族一律收编成类 | 内联样式是令牌体系的地下通道；字号内联是字阶漂移的来源 | `R08` |

运行：`python scripts/design-check.py`，退出码 0 才允许提交。

## 2. 评审军规（机器查不了，走查清单）

改动视觉时逐条自问（来源：《人人都是 UI 设计师》20 条军规，按本项目取舍）：

**层级**
- [ ] 这一屏最重要的元素，是靠**弱化其他元素**凸显的，还是又加了一个更大的字号？（军规 03/04）
- [ ] 能用间距分组的，就没用边框/卡片再包一层？（军规 09/19）
- [ ] 按钮颜色表达的是**视觉权重**，不是「语义色收集癖」？（军规 06）

**排版**
- [ ] 正文行长 ≤ 42 个汉字？超了先缩栏宽，不是缩字号（军规 11）
- [ ] 数字列用 `var(--mono)` + `tabular-nums`，右对齐或基线对齐，不是居中？（军规 12）

**色彩**
- [ ] 信息不只靠颜色传达（涨跌停另有 +/- 号、形状或文字）？（军规 15）
- [ ] 深墨面（--desk）上的颜色用的是 `*-hi` 高可见度变体，不是浅底令牌直接搬？（军规 17 的本项目形式）

**收尾（impeccable「交付收尾」维）**
- [ ] 空态、加载失败、超长按钮文字、零值/负值，四种状态都看过截图？
- [ ] 暗色主题、390px 窄屏、1440px 桌面三档都过了一遍？

## 3. 验收闭环（来源：logo-design-skill「画完必须渲染出来看」）

任何视觉改动，完成定义 = 三件事全做，缺一件不算完：

1. **脚本**：`python scripts/design-check.py` 全绿
2. **渲染**：本地起服务，浏览器实测（不是推断）——桌面 + 窄屏 + 暗色三档截图
3. **交互走查**：控制台 0 报错；改动涉及的交互路径亲手点一遍

「代码写完」≠「做完」。渲染出来的像素才是交付物。

## 4. 双端对齐

- 内容口径（课程数、死法条数、复盘字段）Web 端与 `miniprogram-uni/` 必须一致；改内容先改 `common/*.js` 数据层，两端各自渲染
- 小程序端另有一套设计约束（rpx、`--card` 等变量体系），本规范的 R01/R05/R08 精神同样适用：**新页面样式只许用已有变量，缺变量先补变量**
