# 多端设计规范 · Design System

一套设计语言，三个端：**Web（H5）· 微信小程序 · App**。

- Web 端：`/index.html` + `app.css` + `app.js` + `teachers.js`，单页应用，移动优先，桌面居中显示为设备容器
- 小程序 / App：`/miniprogram-uni`，uni-app（Vue3）工程，一套代码编译到小程序、App、H5
- 文档版：`/playbook.html`（八套策略完整手册，作为「规则」参考页被引用）

---

## 1. 设计原则

| 原则 | 落地方式 |
|---|---|
| **训练场，不是读物** | 每门课配一道图判题；每个概念有可操作的控件，而不是一段说明 |
| **图先于字** | K 线、仓位条、阶段条、进度环——能用图形表达的不用段落 |
| **红涨绿跌** | 严格遵循 A 股习惯：涨 `#d94a45`，跌 `#17855f`；不用欧美配色 |
| **一屏一个决策** | 每个卡片只回答一个问题；详情收进底部抽屉，不铺开 |
| **风险可见** | 违规、回撤、风险等级始终出现在界面上，不做隐藏 |

## 6. 交互规范

- **触控目标** ≥ 44×44px（88rpx），卡片整块可点，不要求点小图标
- **抽屉**：从底部升起，带遮罩，点遮罩关闭；高度不超过 86vh，内部可滚动
- **反馈**：所有可点元素 `:active` 缩放到 0.97–0.99，时长 120ms
- **安全区**：底部导航使用 `env(safe-area-inset-bottom)`，小程序由原生 tabBar 处理
- **状态保持**：Tab 切换不销毁状态；Web 端切换后回到顶部
- **空态**：训练未作答时不给解析；答完才显示，避免剧透

## 8. 老师模块（v3）设计说明

### 8.1 为什么不列人名

用户希望有「网络教金融的老师们」。直接做一个人名 + 头像 + 粉丝数的排行榜，会带来三个问题：

1. **合规风险**：推荐具体自然人涉及投资建议与名誉风险
2. **过时风险**：账号会封、会换、会停更，人名列表三个月就腐烂
3. **教学无效**：记住名字不能提升判断力，识别**流派**才能

所以本模块的落点是：**8 个流派 + 4 类话术**。任何平台上能刷到的"老师"，都会落进这 12 个格子里。
卡片上的 `verified` 字段不是"粉丝数"，而是**可核查程度**——这是全模块最关键的替换。

### 8.2 卡片字段设计（对照参考截图）

参考截图是「师傅厨房」的师傅选择页，它的卡片结构是：`头像 + 名字 + 平台徽章 + 一句话 + 菜系标签 + 课程数 + 进入箭头`。
本模块保留这个骨架，但把每一格都换成"有判断价值"的信息：

| 截图层级 | 师傅厨房 | 本模块 | 替换理由 |
|---|---|---|---|
| 角标 | 小红书 / YouTube | `可核查` / `无业绩` / `无凭证` | 平台不重要，凭证才重要 |
| 名字 | 人名 | 流派名（主线龙头派…） | 避免推荐自然人 |
| 副标题 | 家庭料理 · 暖心型 | 情绪周期 · 打板 | 换成方法特征 |
| 一句话 | 一道菜给你三种做法 | 这个流派**承诺**什么 | 保留"承诺"，因为它最容易识别 |
| 标签 | 家常菜 / 蒸菜 | 适用市况（趋势市 / 发酵期） | 从"口味"换成"何时用它" |
| 底部计数 | 1 道课 · 适合零基础 | 识别难度 · 核查方式 | 从"内容量"换成"识别成本" |
| 点击动作 | 进入他的厨房 | 看**约束条件** | 从"看内容"换成"看边界" |

**核心改动**：截图里点击是"看更多内容"，本模块点击是"看这派的约束条件"——
最低资金、最大仓位、止损方式、交易频率，以及**明确不适合的人**。
后一项（`forbid`）是全部数据里最有价值的一栏。

### 8.3 幻方（Pantheon）布局

4 格 2×2，中心一个 chip：「按「你怎么赚钱」分」。四象限：

| 象限 | 名称 | 包含流派 |
|---|---|---|
| 攻 · 主动 | 择时派 | 主线龙头、事件驱动 |
| 攻 · 被动 | 跟随派 | 趋势跟随、行业轮动 |
| 守 · 被动 | 配置派 | 红利低波、量化多因子 |
| 守 · 主动 | 逆向派 | 价值集中、困境反转 |

点击象限 → 高亮对应流派卡 + 平滑滚动定位；再点一次取消。

**实现注意**：`renderTeachers()` 会整体重绘 `#pantheon`，所以事件监听必须绑在容器上（事件委托），
不能绑在按钮节点上；测试里也不能缓存 DOM 引用后再点。

### 8.4 三端差异

| 项 | Web | 小程序 |
|---|---|---|
| 数据源 | `teachers.js`（IIFE，挂 `window.TEACHERS`） | `common/teachers.js`（ESM export） |
| 幻方中心轴 | `<i class="center-axis">` + 绝对定位 | `.axis.v` / `.axis.h`，rpx 尺寸 |
| 卡片网格 | `grid-template-columns:1fr 1fr` | 同源（小程序支持 grid） |
| 点击反馈 | `:active` 缩放 | 同源 + `uni.vibrateShort` |
| 详情 | 底部抽屉 `.sheet` | 自绘 `view.mask > view.sheet` |

两端数据由 `_test/sync.js` 做字段级 diff 校验，改一端忘改另一端会直接报错。

### 8.5 反面样本的必要性

4 类话术卡（晒单型 / 喊单型 / 内幕型 / 指标神型）使用**斜纹底 + 灰头像 + 红字**，视觉上和真实流派明确区分。
它们的详情页**不含**"可执行的核心规则"，只有"破绽"与"识别信号"——这是刻意的结构差异：
话术没有可执行内容，界面不应该假装它有。

## 9. 成长体系（v4）设计说明

v4 解决的是一个结构性问题：**v3 及之前所有内容都默认用户已经知道股票是什么**。
8 门课第一句就是「核心+卫星」「仓位 = 总资金 × 风险% ÷ 止损幅度%」，
这是给「已经入门、缺方法」的人看的。真正的小白缺的不是策略，是地基。

参考抖音白板科普类创作者（如「小雷大智慧」）的路径——第一条视频讲市盈率，
全程「授人以鱼不如授人以渔」，从不说买什么——v4 把这条路径落成了代码：
**先知道是什么（Lv1），再学怎么做（8 门课），最后找到适合你的那一派（自测 → 老师模块）**。

### 11.1 五段路径

| 段位 | 名称 | 解决什么 | 毕业标准（全部可计算，无自评） |
|---|---|---|---|
| L1 | 启蒙 AWAKEN | 知道你买的到底是什么 | 13 条启蒙概念全部标记已读 |
| L2 | 筑基 DISCIPLINE | 能把一次交易算清楚、执行完 | 前 3 门基础课完成 + 判题 ≥ 5 次且正确率 ≥ 60% |
| L3 | 寻道 EXPLORE | 找到适合你的那一派 | 完成流派自测 + 进阶课 ≥ 3 门 |
| L4 | 系统 SYSTEM | 把选股到复盘串成闭环 | 完成 8 门课 + 复盘 ≥ 7 天 |
| L5 | 化境 MASTERY | 知行合一 | 连续复盘 ≥ 7 天 + 判题最高连对 ≥ 10 |

**为什么强调「无自评」**：段位如果靠用户自己点「我觉得我懂了」，就必然膨胀。
五项标准全部从 `localStorage` / `uni.getStorageSync` 的真实记录里算：
读了就是读了，判题对了就是对了，复盘几天就是几天。

### 11.2 Lv1 启蒙层（13 条）

| 分组 | 条目 |
|---|---|
| 你买的到底是什么 | 01 股票 = 公司的一小块 / 02 市盈率 / 03 市值 |
| 价格怎么读 | 04 K 线 / 05 成交量 / 06 均线 |
| 交易规则 | 07 T+1 / 08 涨跌停 / 09 手续费 / 10 股息 |
| 为什么大多数人亏钱 | 11 财报三张表 / 12 复亏比复利残酷 / 13 牛熊 |

每条固定四个字段：

- `one` —— 一句话结论。先看这个，看不懂再往下读
- `why` —— 为什么重要。回答「不学这个会怎样」
- `mis` —— **常见误解**。这一层最关键的字段：科普最大的价值不是告诉你什么对，而是提前拆掉你脑子里那个错的版本
- `eg` —— 举个具体数字的例子

**不讲任何策略**：13 条里没有一条告诉用户该买什么。这是刻意的——
Lv1 的地基一旦沾上「战法」，用户就会跳过理解直接抄结论，后面全崩。

### 11.3 流派自测（8 题）

三道硬约束：能投入多少时间、能承受多大回撤、本金规模。
选项用权重打分（`w: { longtou: 2, trend: 1 }`），累加后取最高分派别。

**陷阱项机制**：部分选项 `w` 为空对象。这些是「八派全部反对」的动作
（如「补仓摊低成本」「一亏就换策略」）。UI 上它们会被标成警示色，
选了不扣分但会直接弹出为什么——**它的作用是教育，不是筛选**。

自测结果直接输出该派的约束条件（最低资金 / 最大仓位 / 止损方式 / 交易频率 / 明确不适合的人），
并可一键跳到老师模块对应流派。

**为什么不叫「测评」叫「自测」**：结果只反映用户**现在**的条件。
资金量、可投入时间变了，答案就变了。结果页明确写了「建议资金或时间发生重大变化时重测一次」。

### 11.4 三端实现差异

| 位置 | Web | 小程序（uni-app） |
|---|---|---|
| 数据 | `basics.js` / `rank.js` / `quiz.js`，挂 `window.BASICS` 等 | `common/*.js`，ESM `export` |
| 状态读取 | `store.get(key, default)`（localStorage 封装） | `uni.getStorageSync(key)` |
| 段位计算 | `RANKS.current(store)` | `current()`（内部自己读 storage） |
| 弹层 | 同一个 `#sheetBody` 复用，四种内容切换 | `mode` 字段切换：`course` / `basic` / `rank` / `quiz` / `qres` |
| 跨页跳转 | `go('teacher')` + `openTeacher(k)` | `uni.setStorageSync('ta_open_school', k)` + `switchTab`，teacher 页 `onShow` 消费后清除 |

小程序端没有 Web 那种「路由后立刻调用方法」的能力（tabBar 页面已实例化），
所以用 storage 做一次性传参：`ta_open_school` 写入 → 切 tab → `onShow` 读取 → 立即删除。

### 11.5 新增本地存储键

| key | 内容 |
|---|---|
| `ta_basics` | 已读启蒙条目编号数组，如 `['01','02']` |
| `ta_quiz` | 自测结果 `{ top, score, share, second, ranks }` |
| `ta_open_school` | 一次性跨页传参（用完即删），不是持久化数据 |

### 11.6 一致性保障

三端数据不允许「各写一份」：

- `tools/check.js` —— 用 git blob sha1 比对本地与远端，列出新增 / 变更 / 远端多出
- `upload.js` 的 `precheck()` —— 上传前比对 15 组文件对的 md5（Web 源 ↔ 发布目录 ↔ 根 uni 镜像），不一致直接中止
- `_test/diff-v4.js` —— 跑数据层逐字段比对：13 条启蒙 × 8 字段、5 段 × 7 字段、
  6 组状态 × 5 段毕业判定、8 题选项与权重、4 组作答的 `result()` 返回值

本次发现的真实不一致（已修）：

1. Web 端 L3 的 `ok: st.quiz && adv >= 3` 在未自测时返回 `null` 而非 `false`，小程序端是 `!!st.quiz` —— 已统一为 `!!`
2. 小程序端 4 个反面样本缺 `right` 字段，导致详情页「教对了什么」一栏空白 —— 已补齐 `right: '—'`

## 12. 亏损案例库（v5）设计说明

### 12.1 为什么单独做这块

启蒙层回答「是什么」，8 门课回答「怎么做」，老师模块回答「跟谁学」。
但从小白到真正能做决策之间，拉开差距的**不是学了多少种方法，而是见过多少种死法**。

- 没见过的人：每种死法都要用自己的钱买一次
- 见过的人：第一次遇到就能认出来

这是可训练的经验里唯一能低成本批量传递的部分——方法需要实盘验证，死法不需要。

### 12.2 16 个场景的四组

| 分组 | 场景 |
|---|---|
| 买之前就错了 | 听朋友说要涨 / 只看涨幅榜选票 / 低价股更便宜 / 财报好看就买 |
| 仓位上的死法 | 一把梭 / 跌了就补摊低成本 / 盈利的先卖亏损的留着 / 用杠杆加速 |
| 卖点上的死法 | 不设止损怕被扫 / 赚钱不敢拿亏钱死扛 / 回本就卖 / 退潮了还在找下一只 |
| 过程中的死法 | 频繁交易 / 一亏就换策略 / 不复盘只换股 / 跟着"老师"做单 |

### 12.3 每条固定五段

| 字段 | 作用 |
|---|---|
| `scene` | 场景：你当时在干什么（具体到动作，不是抽象描述） |
| `think` | 你以为：当时脑子里那句话 |
| `real` | 实际发生了什么 |
| `fix` | 正确做法：**可执行**，不是「要心态好」 |
| `link` | 相关启蒙条目编号（可选，用于跳转） |

**刻意不使用任何真实个股名称、日期、人物**。这些场景是**类型**不是个案：
一旦用了真名，读者会去搜「那只票」，而不是去理解机制。

### 12.4 与启蒙层的联动

案例的 `link` 指向启蒙条目编号（如 d06 摊低成本 → 24 号，d09 不设止损 → 03 号）。
案例是**反例**，启蒙条目是**正解**——从死法点进去能看到「为什么」，形成闭环。

### 12.5 数据不再手写两份

三端各写一份数据必然漂移，已经踩过两次（L3 的 `null` vs `false`、反面样本缺 `right`）。
纯数据块现在只有一个源头：

```bash
node tools/gen-uni.js      # 从 Web 端 basics.js / deaths.js 生成小程序端 ESM
```

生成物带「请勿手改」头注释。`common/rank.js` 仍手工维护（要换成 `uni.getStorageSync`），
靠 `_test/diff-v4.js` 校验。

### 12.6 关于电脑端

**已确认不做**：本项目定位是移动端 App + 网页版（H5）。
Web 端 `.device` 固定 `max-width:520px` 居中，在桌面上呈现为手机框——这是刻意的产品选择，
不是未完成的适配。曾实现过一套 ≥900px 的宽屏布局（侧边导航 + 双栏 + 居中弹窗），
按需求已整体移除，未残留任何 `sidebar` / 宽屏 media query 代码。

## 13. 训练场题库（v6）设计说明

### 13.1 为什么要改

自己完整走了一遍新手旅程（`_test/journey.js`）后发现训练场**只能玩一轮**：

- 只有 6 道题，循环出题，做满一轮后每题答案都见过了；
- 每个 `seg()` 的 seed 都是写死在源码里的常量 → 同一题型每次生成**逐帧一致**的 K 线；
- 结果：正确率和连对都是背出来的，L5 的「连对 ≥10」变成重复刷题的产物，不是能力。

### 13.2 三个改动

1. **题库 6 → 10 题**：新增箱体震荡、利好高开低走、止损后重新站回、加速赶顶。
2. **每次出题换随机路径**：所有 seed 走 `sd(base) = base + salt * 7919`，salt 每轮换一次。
   `drift / vol / 量能倍数` 保持不变，所以形态的方向、幅度、量能特征守恒，只是走势不同。
3. **选项重新编号**：A/B/C 随机分配给三个语义位置，`opts` 和 `marks` 用**同一套编号**
   （保证「图上 B 点」永远对应「选项 B」），列表顺序再洗一次，避免正确答案总排在同一位。

配套约束：解析文案里**不出现 A/B/C 字样**，否则洗牌后读不通（`diff-v4.js` 有这条断言）。

### 13.3 形态守恒靠 check()

随机路径可能走形（比如「突破」没突破成）。所以每题配一个 `check(c)`，
`buildOne()` 换 salt 重画最多 24 次，仍不合格就回退 `salt = 0`
（原始手写 seed，形态必然成立）。校验的是形态本身，不是数值：

| 题 | check 什么 |
|----|-----------|
| 放量突破前高 | 突破价 > 前高，且回踩不破成本区 |
| 高位放量长上影 | 前面确实在涨，上影是最高点，之后确实回落 |
| 跌破颈线 | 颈线在 d 段被实体跌破，第二个头不高于第一个头 |
| 缩量阴跌 | 跌幅够，后段量柱峰值 < 前段 45% |
| 回踩均线不破 | 整体上行，回踩幅度在 2%–14%，之后创新高 |
| 无量反弹到前高 | 反弹高点够到前高 88%–102%，量能 < 前段 62% |
| 箱体震荡 | 振幅 < 28%，收在箱体内 |
| 利好高开低走 | 高开 >3%、收阴、之后继续走弱 |
| 止损后重新站回 | 确实破位过，之后放量站回原位 |
| 加速赶顶 | 前段慢涨、后段加速、量能放大 |

### 13.4 单一数据源

题库不是纯数据（带 `build()` / `check()`），`gen-uni.js` 的 `JSON.stringify` 方案会丢函数。
所以新增 `tools/gen-cases.js`：Web 端 `cases.js` 用 `BODY:BEGIN / BODY:END` 包住一段
平台无关代码，脚本原样搬到小程序端再补 ESM 导出，并做 `document / window / uni` 自检。

```bash
node tools/gen-cases.js    # 从 Web 端 cases.js 生成小程序端 common/cases.js
```

小程序端原来的 `common/kline.js`（手写 2 道题）已删除，`train.vue` 改用 `common/cases.js`。

### 13.5 顺带修掉的体验问题

**Lv1 启蒙 25 条要 50 次点击**（点开 + 再点「标记已读」）。改成**打开即已读**，
抽屉里的按钮变成「✓ 已读 · 标记未读」用于回退。点开了就是在读，
没必要让用户再确认一次。Web 端 `app.js:openBasic` 与小程序端 `learn.vue:openBasic` 同步改造。

### 13.6 回归

| 脚本 | 覆盖 |
|------|------|
| `_test/v4.js` | 75 项功能回归（含打开即已读 / 可回退） |
| `_test/diff-v4.js` | 47 项三端一致性（含题库 10 题 × 30 轮的 mark 下标、标签、答案唯一性、洗牌有效性） |
| `_test/journey.js` | 新手全流程体检，0 项待优化 |
| `_test/sync.js` | 三份本地副本同步 |

`journey.js` 的随机性检查用 40 轮采样而不是 DOM 走 12 题——3 个样本撞同一个字母有
1/9 概率，会误报。

### 13.7 第二轮体检（`_test/journey2.js`）

第一轮只走了「学院 → 训练场 → 我的」主链路。补一轮覆盖剩下的入口：
仓位计算器 / 模拟盘跳转 / 情绪周期 / 我的（成就 · 复盘 · 判题统计）/ 答对计分链路。

发现并修掉：

1. **仓位计算器金额栏显示 NaN**：原式 `cap*risk/100/(stop/100)/cap*100` 里 `cap` 会被约掉，
   总资金填 0 时变成 `0/0`。`cOut` 用 `isNaN(pct)?0` 兜住了，但 `cAmt` 用的是未兜底的 `pct`，
   于是出现「约 NaN 万元」。改成 `pct = Math.min(risk/stop*100, mx)`，并在 `cap/risk/stop <= 0` 时直接给 0。
2. **`trade-academy/playbook.html` 一直不存在**：模拟盘按钮跳 `playbook.html#sandbox`，
   但这个文件只在发布目录里，Web 源目录缺失——本地跑起来点模拟盘是 404。
   已补进 `_test/sync.js` 的同步清单和 `upload.js` 的预检清单（之前两组都没覆盖它，所以漂移没被发现）。

确认没问题的：情绪周期 4 阶段切换与高亮、策略矩阵 4 张、复盘勾选落盘 `ta_review_YYYY-M-D`、
4 个成就徽章、「先看解析」不计分（等于放弃本题，点了就不能再选）。

## 14. 界面风格（v7）

### 14.1 为什么做

内容已经不缺了（25 条启蒙 / 8 门课 / 10 道 K 线题 / 16 个死法），但视觉只有一套。
有人白天通勤看、有人夜里看盘看、有人只想安静读 25 条启蒙——同一套配色伺候不了三种场景。
所以把「长什么样」做成可选项，内容不动。

### 14.2 五套

| key | 名字 | 关键差异 |
|-----|------|----------|
| `light` | 晨光蓝 | 默认。券商蓝白，`--r-lg:20px` |
| `dark` | 夜航深 | 深底 `#0e131a`，品牌色转亮蓝，涨跌色提亮 |
| `paper` | 纸感暖 | 米白纸底 + 衬线标题，`box-shadow` 去掉 |
| `mono` | 极简黑白 | 纯黑白，去掉所有渐变/阴影，圆角缩到 14px |
| `celadon` | 青瓷 | 低饱和青绿，`--brand:#12594c` |

刻意没做「朱红金」：A 股里红=涨，界面大面积红会干扰盘面语义。

### 14.3 变量契约

主题只覆盖 CSS 变量，不覆盖组件规则（`mono` 有三条例外，见 14.5）。
变量分三类：

1. **基础**：`--bg --bg-2 --card --card-2 --ink --ink-2 --muted --line --line-2`
2. **语义色**：`--brand* --up* --down* --gold*` + `--ok-* --bad-* --gold-*`（前后缀两套，前者是主色，后者是浅底/深字配对）
3. **结构**：`--r-lg --r --r-sm`

新增一套主题 = 在 `themes.css` 补一段 `[data-theme="x"]{}` + 在 `theme.js` 的 `THEMES` 里加一行。
其余（小程序变量段、画布配色、选择卡片）要么自动生成，要么读变量。

### 14.4 画布颜色为什么单独一份

`<canvas>` 的 `fillStyle` 不接受 `var()`，`getComputedStyle` 在小程序端也不可用。
所以在 `theme.js` 里放 `CANVAS` 表（每套 13 个色值），Web 端 `drawK()` 和
小程序端 `train.vue` 都读它。**这是唯一的双份位置**，但只有一份数据。

### 14.5 三处例外（不是遗漏）

- `mono` 的 `.hero / .rankcard / .topbar .mark` 强制 `background-image:none`；
- `paper` 的标题改衬线（正文保持无衬线，移动端小字宋体会糊）；
- `dark` 的 `.btn-ghost` 和 `.mark` 单独调了半透明值。

### 14.6 校验

`_test/theme.js`（113 项）：

- 主题集合 / 元数据 / 变量完整性；
- **涨=红、跌=绿** 五套全查（含画布色）；
- 主文字/卡片 ≥ 7:1、次文字 ≥ 4.5:1、主文字/页底 ≥ 7:1；
- 小程序端生成物 == Web 端源（元数据 + 每套颜色逐个比对）；
- 接线检查（引入、容器、5 个页面挂类、canvas 读色表）；
- 三份副本 md5 一致。

`_test/theme-ui.js`（22 项）：jsdom 里真点卡片，验 `data-theme` / 落盘 / 选中态 / `?theme=` 参数 / 参数用完即抹。

### 14.7 踩坑

- **小程序样式是编译期 scss 变量**，运行时切主题必须先改成 CSS 变量。
  做法：`uni.scss` 里 `$card: var(--card);`（scss 变量只是文本替换），页面样式一行不用改。
- **改小程序要改根级 `miniprogram-uni/`，不是发布目录**。`_test/sync.js` 方向是
  根级 → 发布目录，改错边会被同步覆盖（这次就丢了一轮改动，重做了一次）。
- **`themes.css` 的特异性**：`:root` 和 `[data-theme="x"]` 都是 0,1,0，
  靠「后加载」取胜。所以 `themes.css` 必须排在 `app.css` 之后。

## 15. 学习机制（v8）

### 15.1 为什么做

v7 结束时内容已经够用：25 条启蒙、8 门课、10 道 K 线题、16 个死法、5 套主题。
问题是**没有理由第二天再打开**——读完就完了，学没学会没人问，学过什么也看不见。

参考了多邻国（连击 / 经验 / 每日目标 / 十题一组）和百词斩（一问一答 + 错题本 + 掌握度），
但只借机制，不搬糖水：

| 借了 | 没搬 | 为什么 |
|------|------|--------|
| 连续打卡（streak） | 生命值 | 学习不该有「答错就死」的惩罚，会让人不敢答 |
| 每日小目标 | 排行榜 | 投资本来就容易和别人比收益，学习环节不该再加一层攀比 |
| 经验值 + 段内进度 | 付费加速 / 充值 | 这是教学工具，不是游戏，不设付费点 |
| 十题一组（有终点） | 无限刷 | 无限刷最后是麻木，正确率虚高却什么都没记住 |
| 掌握度（对两次才算会） | 连对分数排行 | 掌握度只给自己看，用于决定下一组出什么题 |

### 15.2 两条账，分开记

这是这一版最重要的设计判断：

- **段位（`rank.js`）只认真实成果**：读完多少条、完成几门课、判对多少题、复盘几天。
- **经验值（`learn.js`）只负责本段内的进度感**：`SEG_XP = 200` 一段，跨段在 HUD 上做一个 bump 动效，仅此而已。

经验值**不能**影响段位判定。这条约束是硬的，不是约定：

- `learn.js` 不 import、不读写 `ta_done` / `ta_basics`；
- `rank.js` 不读 `ta_prof`，全文没有 `.xp`；
- `_test/v8.js` 第 12 节直接扫两个文件的源码，出现越界就红。

为什么值得专门写一条测试：一旦经验值能买段位，段位就成了刷分游戏，
而「读完 25 条启蒙」这种真实门槛反而被绕过——那这套成长体系就白做了。

### 15.3 连击与补签

只在**今天第一次学习**时结算（`touch()`），一天只加一次：

```
今天已学过        → 不动
昨天学过          → +1
昨天用了补签卡    → 保持（≥1）
其他（断了）      → 归 1
```

补签卡（freeze）刻意做得不显眼：

- 只能补**昨天**，一次一天，上限 9 张；
- 只有真的断了才在今日卡里露出一条提示；
- 初始不发卡，靠「连续满 7 天」奖励。

理由：断签最容易让人彻底放弃（「反正断了」）。补签卡是给一次台阶，
但不能变成「反正能补」。所以它不放在醒目位置，也不卖。

**断两天以上归 1 而不是归 0**：归 0 和归 1 效果一样，但归 1 不羞辱人。

### 15.4 掌握度模型

每张概念卡独立记 `{ r, w, level, last }`：

| level | 含义 | 怎么到 |
|-------|------|--------|
| 0 | 新卡 | 初始 |
| 1 | 生疏 | 答错一次（`r` 清零） |
| 2 | 熟悉 | 答对一次 |
| 3 | 掌握 | **连对两次**（`r >= 2`） |

答错一律掉回 1，不设「答错永久留级」——那会让错题队列永远清不完，
用户看到的永远是一个清不掉的红点，最后就不看了。

`level === 1` 才算「错题」，会进下一组的优先池。

### 15.5 十题一组：`SESSION = 10`

`buildSession(list, stat, n, only)` 的抽题规则：

1. 先取错题（`level === 1`），但**最多占一半**——一组全错题会挫败，一组全没做过又显得白卷；
2. 剩下的按组轮换，保证三组都能碰到，不让人一直在「概念地基」里打转；
3. 池子比组小的时候允许重复，但不连续重复同一张。

选项每次 Fisher-Yates 洗牌：题库固定（概念题本来就该能背下来），
但**记的应该是道理，不是「第三个选项」**。洗牌后正确答案位置重算，
`_test/v8.js` 里跑了 4000 题验分布，A/B/C/D 各 ≈ 25%。

### 15.6 会话状态不落盘

`QZ` 只存内存，关掉就重来。理由不是偷懒：

一组才三分钟。半场回来的人已经不记得第几题、也不记得前面错过了什么，
续着答只会更乱。与其花代码做「会话恢复」，不如让它干脆重来。

落盘的是**结果**：`ta_cardstat`（总题数/对数/连对/最好连对/组数）、
`ta_mast`（每张卡的掌握度）、`ta_prof`（经验、连击、日志）。

### 15.7 数据自救

localStorage / 小程序 storage 随时可能被清（换机、清缓存、隐私模式），
而段位是靠几十天记录算出来的——清一次等于从头再来，这是最伤人的失败方式。

所以「我的」页给了**导出 / 导入**：

- 导出：`{ v:8, at:'Y-M-D', data:{…} }`，包含 9 个固定键 + 扫 400 天的 `ta_review_*`；
- 导入：逐键校验类型后写回，失败给出具体哪一项不对。

比写一百句「请勿清除缓存」有用。

### 15.8 新模块与三端同源

| 文件 | 作用 |
|------|------|
| `learn.js` | 经验 / 连击 / 补签 / 掌握度 / 本周 / 段内等级（BODY 段平台无关） |
| `cards.js` | 24 张概念卡，三组：概念地基 9 / 算得清 7 / 守得住 8 |
| `srs.js` | 出题引擎：洗牌、抽组、错题优先、计分 |

小程序端不是重写，而是 `tools/gen-learn.js` 从 Web 端 BODY 段切片生成
（`miniprogram-uni/common/{learn,cards,srs}.js`），并补两点适配：

1. `store` 适配层：`uni.getStorageSync / setStorageSync` 包成和 Web 端同签名的 `{ get, set }`，
   所以规则代码一行都不用改；
2. `const API = {…}` 转成 `export {…}`，`size = CARDS.length` 这类计算项落成普通 `const`。

`_test/sync.js` 会逐字比对**规则段**（切到 `const API = {` 之前），
源改了忘记重新生成会直接报「规则不一致」。

### 15.9 校验

`_test/v8.js`（140 项）：

## 16. 自创流派（v9）

### 16.1 为什么做

到 v8 为止，学院里有八派：主线龙头、趋势跟随、价值集中、行业轮动、量化多因子、
红利低波、事件驱动、困境反转。每一派都有「教对了什么 / 教漏了什么 / 识别陷阱 /
可执行规则 / 谁不该用」。

但八派有一个共同的问题：**它们都是别人的答案。**

真到自己的账户上，没有人是纯粹的一派。你一定在某些条件下用 A、另一些条件下用 B——
这不是不纯粹，这是正常状态；不正常的是一边混用、一边不承认。

所以第九派不是「更好的方法」，是一台装配台：把八派拆成零件，让用户自己装一遍，
再自己写下它什么时候会失效。

### 16.2 为什么不给"你的流派成熟度 87%"

这是本模块最重要的一条取舍。

多邻国式的产品很容易滑向"打分表扬"——填了三个格子就 +50 经验、弹出"你已超过 92% 的用户"。
这套东西对语言学习有效（因为学习本身没有对错），但对交易策略是有毒的：
一个自洽但错误的策略，配上"成熟度 87%"的表扬，等于给了用户实盘的勇气。

所以这里只做**布尔判断**，不做好看的分。三道闸，全过才叫挂牌：

| 闸 | 判定 | 为什么卡这一条 |
|---|---|---|
| 规则 | 六格里至少填 4 格（非空且 ≥2 字） | 少于四条不成体系 |
| 禁区 | 第 5 格「我明确不做的事」必填 | 没有禁区的体系一定有漏洞 |
| 检验 | 12 个场景至少答对 10 个 | 自己写的规则，自己都解释不了过去的场景，就是没想清 |

「挂牌」这个词也是刻意的：不是「可以实盘」，只是「自洽」。页面上写死了这句话。

### 16.3 六个格子

名字用口语，不用术语——想不清「触发条件」的人，换成「什么条件下才买」也还是想不清，
但至少知道该想什么。

| # | 格子 | 填错时通常长什么样 |
|---|---|---|
| 1 | 什么条件下才买 | 「感觉要启动了」——回测时你会自动打勾，实盘时你会自动不打勾 |
| 2 | 一次买多少 | 不写数字等于「看心情」，而看心情的结果永远是满仓 |
| 3 | 什么情况下认错 | 「跌多了再说」不是止损，是把决定权交给情绪 |
| 4 | 什么情况下卖出 | 只有买入规则没有卖出规则，等于只有油门没有刹车 |
| 5 | **我明确不做的事**（必填） | 想不出来，说明还没找到自己最容易犯的那个错 |
| 6 | 它在什么情况下会失效 | 说不出失效条件的策略不是策略，是信仰 |

第 5 格可以从八派的禁止条款里一键借（`SEEDS`，8 条），借来默认落进禁区。
第 6 格故意不给可借项——失效条件只能自己写。

### 16.4 12 个场景为什么能给"对错"

这道题最容易做错的地方是：拿真实行情当题，答案会随行情过时。

所以 12 个场景只给**处境**，不给行情：主线连续涨停后追高、亏损后补仓摊低成本、
单笔浮亏超止损、浮盈超预期一倍、大盘缩量阴跌、听到一个"很确定"的消息、
连续 5 次止损、身边人都在赚钱、一字板涨停次日可能打开、买入理由被证伪、
空仓一个月、看到大 V 晒翻倍收益。

每个处境给两个说法，一个"守规则"、一个"顺着人性"。答案的对错**永远按
「有没有遵守你自己写的规则」判**——所以这套题不会过时。

### 16.5 「补仓」那条单独处理

第 2 个场景（亏损后补仓摊低成本）选错时，结论不是"不通过"，而是降级：

- 全过 → `可以挂牌`
- 补仓那条选错 → `可以挂牌，但先想清补仓那条`

理由：补仓摊低成本是八派**全部**反对的少数动作之一（`quiz.js` 的陷阱项、
`deaths.js` 的死法、`basics.js` 的启蒙都提到过）。它也是小亏变大亏的标准路径。
用户在这里选了"顺着人性"，说明规则和真实行为不一致——这时候给一句"通过"是在害人。

### 16.6 与段位的关系：没有关系

`craft.js` 全文不写 `addXp`、不碰 `ta_prof`、不读 `rank.js`。
草稿不产生经验值，也不影响任何段位判定。

这是 `15.2 两条账分开记` 的延续：段位只认真实成果，草稿是一张纸。
`_test/v8.js` 第 17 节用源码扫描固化这条（`craft.js` 只能 `store.get/set` 各一次，
且只碰 `ta_craft`；`rank.js` 不出现 `ta_craft`）。
